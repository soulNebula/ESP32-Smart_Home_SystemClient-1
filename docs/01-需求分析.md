# 01 需求分析

> 本文把用户最初提出的 **7 条需求原文** 逐条拆解成「技术解读 / 涉及硬件 / 涉及代码模块 / 验收方式」，
> 最后给出需求→模块对照总表，以及本期范围与后续可扩展的边界。
> 所有引脚、宏名、模块名均取自源码，未做任何臆测。

## 1. 需求逐条拆解

### 需求 1

> **原文**：光传感器，当光照大于或小于某个阈值时灯会亮或者窗帘关上

| 项 | 内容 |
|----|------|
| **技术解读** | 光传感器 → 阈值判断 → 驱动「客厅灯带」和「窗帘舵机」。**两个执行器动作方向相反**：暗了要**开灯**、同时把窗帘**合上**（遮光/保温）；亮了要**关灯**、把窗帘**拉开**（自然采光）。为避免光照在阈值附近抖动导致灯反复开关，采用**双阈值迟滞**：`lux < light_on_lux` 才开，`lux > light_off_lux` 才关，中间区间保持不动。 |
| **涉及硬件** | 光敏电阻 GL5528 + 10kΩ（GPIO1 / ADC1_CH0）**或** BH1750 I2C 光照模块（0x23）；客厅 WS2812 灯带（GPIO4）；窗帘舵机（GPIO15）。 |
| **涉及代码模块** | `BSP/ADC/adc_bus.c`（ADC1 采样+校准）、`BSP/SENSOR/sensor.c`（光照换算、自动识别 BH1750）、`App/automation.c` 规则1（`auto_light_enable`，阈值 `light_on_lux` / `light_off_lux`）、`App/device_model.c`（落到 `DEV_LED_LIVING` / `DEV_CURTAIN`）、`BSP/LED/led.c`、`BSP/SERVO/servo.c`。 |
| **验收方式** | ① 串口 `status` 能看到 `lux` / `light_pct` 随遮光变化；② `cfg light_on_lux 50` 后用手遮住光敏电阻，客厅灯带亮起、窗帘舵机转到 `level=0`（合上）；③ 用强光照射，灯灭、窗帘转到 `level=100`（拉开）；④ 阈值附近缓慢变化时不出现反复横跳。 |

### 需求 2

> **原文**：温湿度传感器，OLED 显示温湿度，当温度高于某个值，风扇打开，小于则关闭。也可以语音控制

| 项 | 内容 |
|----|------|
| **技术解读** | 三件事：① I2C 读取温湿度；② OLED 上显示；③ 温度超过阈值开风扇、低于另一阈值关风扇（迟滞），并且**风扇开关也支持语音**。风扇用 MOS 管做 PWM 调速，25kHz 超出人耳听觉、不会有 PWM 啸叫。 |
| **涉及硬件** | SHT30（0x44）或 AHT20（0x38）温湿度模块；0.96" SSD1306 OLED（0x3C，与传感器共用 I2C0）；MOS 管模块 + 风扇（GPIO18，LEDC 25kHz）。 |
| **涉及代码模块** | `BSP/SENSOR/sensor.c`（SHT30/AHT20 自动识别、CRC 校验、一阶低通滤波）、`components/astra_ui`（OLED 页面渲染，u8g2 画布 → `oled_write_page()`）、`App/automation.c` 规则2（`temp_fan_on_c` / `temp_fan_off_c` / `fan_auto_speed`）、`BSP/FAN/fan.c`、`BSP/VOICE/voice.c` 的 `VOICE_CMD_FAN_ON` / `VOICE_CMD_FAN_OFF`。 |
| **验收方式** | ① 串口 `status` 里 `T:26.5C H:58.2%` 与真实环境一致；② OLED 上显示温湿度；③ 用热风/手捂传感器让温度 > `temp_fan_on_c`（默认 28℃），风扇按 `fan_auto_speed`（默认 70%）转起来，降到 < `temp_fan_off_c`（默认 26℃）后停；④ 说 "打开风扇 / 关闭风扇"（或串口 `say fan_on`）能立即生效；⑤ 不接温湿度传感器时 `valid_temp=false`，温度联动自动停用且不报错。 |

### 需求 3

> **原文**：雨滴传感器，控制窗户开或者关

| 项 | 内容 |
|----|------|
| **技术解读** | 雨滴模块 AO 输出模拟量 → 换算成 0~100% 湿度（越大越湿）→ 超过阈值判定下雨 → **关窗**（窗户舵机转到 0%）。雨停后是否自动开窗由 `auto_window_reopen` 决定，**默认 false**（安全起见不自动开窗）。 |
| **涉及硬件** | 雨滴传感器模块（AO → GPIO2 / ADC1_CH1；DO → GPIO12 可选，不用也能跑）；窗户舵机（GPIO16）。 |
| **涉及代码模块** | `BSP/ADC/adc_bus.c`、`BSP/SENSOR/sensor.c`（`rain_pct` / `rain_detected`）、`App/automation.c` 规则3（阈值键 `rain_pct`、`auto_rain_enable`、`auto_window_reopen`）、`App/device_model.c`（`DEV_WINDOW`）、`BSP/SERVO/servo.c`。 |
| **验收方式** | ① 串口 `status` 看到 `Rain:xx.x%` 随滴水上升；② 把 `cfg rain_pct 30` 后滴水使 `rain_pct > 30`，窗户舵机转到 `level=0`（关窗）；③ 擦干后若 `cfg auto_window_reopen 1` 则自动开窗，为 0 则保持关窗；④ `cfg auto_rain_enable 0` 后规则完全不再动窗户。 |

### 需求 4

> **原文**：厨房、客厅、浴室、卧室 LED 灯的开关，可以进行语音交互控制

| 项 | 内容 |
|----|------|
| **技术解读** | 4 个房间各一路独立 WS2812 灯带。**ESP32-S3 只有 4 个 RMT TX 通道**，正好被 4 路灯带占满（这也是板载状态灯改用位带驱动的原因）。每路支持开关、亮度（软件调光，缩放 RGB）、颜色；颜色会被记住，关灯再开灯沿用。 |
| **涉及硬件** | 4 条 WS2812B 灯带：客厅 GPIO4、厨房 GPIO5、卧室 GPIO6、浴室 GPIO7，每条 30 颗（`BSP_WS2812_LED_NUM_*`），**各自需要 5V 供电**。 |
| **涉及代码模块** | `BSP/WS2812/ws2812.c`（RMT 后端 + 位带后端）、`BSP/LED/led.c`（分区语义）、`App/device_model.c`（`DEV_LED_LIVING/KITCHEN/BEDROOM/BATH`）、`BSP/VOICE/voice.c`（8 条单房间指令 + `LED_ALL_ON/OFF`）、`main/main.c` 的 `voice_on_cmd()`。 |
| **验收方式** | ① 串口 `on led_kitchen` / `off led_kitchen` / `set led_bedroom 30` / `color led_living 255 0 0` 逐路生效；② `say led_bath_on` 模拟语音点亮浴室灯；③ 语音模块接上后说"打开客厅灯"能立即点亮；④ 一路灯带不接不影响其它三路（`led_init()` 单路失败只告警）。 |

### 需求 5

> **原文**：舵机控制门开和关

| 项 | 内容 |
|----|------|
| **技术解读** | 门舵机用 LEDC 硬件 PWM 输出 50Hz、500~2500us 脉宽。工程里舵机统一用 **0~100 的"开合位置"** 表达（`>=50` 视为"开"），`open` ≡ `set value=100`，`close` ≡ `set value=0`。三路舵机（窗帘/窗户/门）**共用 LEDC_TIMER_0**（50Hz 必须一致），各占一个通道。 |
| **涉及硬件** | 门舵机 → GPIO17（信号线，橙色）；另外窗帘 GPIO15、窗户 GPIO16。舵机必须**独立 5V 供电并与开发板共地**。 |
| **涉及代码模块** | `BSP/SERVO/servo.c`（`servo_set_percent()` / `servo_set_angle()` / `servo_detach()`）、`App/device_model.c`（`DEV_DOOR`，`device_set_power()` 对舵机内部转成 `device_set_level()`）、`BSP/VOICE/voice.c` 的 `VOICE_CMD_DOOR_OPEN` / `VOICE_CMD_DOOR_CLOSE`、MQTT `{"dev":"door","action":"open"}`。 |
| **验收方式** | ① 串口 `open door` / `close door` 舵机转到两端；② `set door 50` 停在中位；③ 语音 `say door_open` / 手机 App 发 `{"dev":"door","action":"open"}` 都能开；④ `device_all_off(SRC_MQTT)`（`off all`）后舵机全部归位到 0%。 |

### 需求 6

> **原文**：语音交互控制所有 LED 灯的开关，风扇开关，窗户开关，门开关，或者播报当前温度和湿度

| 项 | 内容 |
|----|------|
| **技术解读** | 语音被抽象成一个枚举 + 一个回调：`voice_cmd_t` 共 **26 个枚举值**（`VOICE_CMD_MAX = 26` = 25 条可用指令 + `VOICE_CMD_NONE`），覆盖单房间灯 8 条、全部灯 2 条、风扇 2 条、窗户 2 条、门 2 条、窗帘 2 条、查询播报 5 条、自动模式开关 2 条。**真实语音模块**（UART1 解析）和**手动注入** `voice_inject_cmd()` 走完全相同的下游链路 `voice_dispatch()`，所以模块没到货也能全链路验证。播报用 `voice_speak()` / `voice_speak_temp()`：传负数表示"这一项不播"。 |
| **涉及硬件** | 语音模块（SU-03T / ASRPRO / LD3320 等串口命令词模块），UART1：ESP32 TX=GPIO47 → 模块 RXD，ESP32 RX=GPIO21 ← 模块 TXD，9600 8N1，**必须共地**。 |
| **涉及代码模块** | `BSP/VOICE/voice.c/.h`（`name_table[]` 26 项、`voice_seq[]` 单字节序号映射）、`main/main.c` 的 `voice_on_cmd()`（语音→设备的唯一耦合点）、`BSP/SENSOR/sensor.c`（播报取 `sensor_get_last()`）。 |
| **验收方式** | ① 串口 `help-voice` 列出全部 25 条指令名（不含 `none`）；② `say query_all` 能播报温湿度，`say query_temp` 只播温度；③ 接上真实模块后说命令词等效；④ 拔掉模块不报错，`voice_is_online()` 30 秒无字节后自动回 false；⑤ 用 `say` 逐条走完 25 条指令，设备动作与指令名一一对应不串位。 |

### 需求 7

> **原文**：终端交互，手机 App 控制所有 LED、风扇、门、窗户等开关

| 项 | 内容 |
|----|------|
| **技术解读** | 「终端交互」用**串口调试台**实现（`CONFIG_APP_SERIAL_DEBUG_ENABLE`，默认开）；「手机 App」用 **MQTT** 实现。topic 基础前缀 `base = <CONFIG_APP_MQTT_TOPIC_PREFIX>/<唯一ID>`，唯一 ID 默认取 **MAC 后 3 字节**（避免在公共 broker 上和别人撞车）。设备一上线发 retained 的 `state`，状态一变自动重发，断线靠 LWT 发 `offline`。 |
| **涉及硬件** | 仅需 WiFi 路由器（2.4GHz）+ 一台跑 MQTTX 的手机/PC；无额外硬件。 |
| **涉及代码模块** | `App/wifi_sta.c`（STA + 自动重连 + `wifi_get_mac_suffix()`）、`App/mqtt_app.c`（订阅 `cmd`/`config`/`get`，上报 `state`/`sensor`/`ack`/`event`/`availability`）、`App/mqtt_protocol.c/.h`（topic 拼装）、`main/main.c` 的串口调试台（`serial_console_task`）。 |
| **验收方式** | ① MQTTX 连 `broker.emqx.io:1883`，订阅 `smarthome/+/state` 能看到本机状态；② 发布 `{"dev":"led_living","action":"on"}` 到 `base/cmd`，灯亮且 `ack` 回 `{"action":"on","ok":true,...}`；③ 发布任意内容到 `base/get` 立刻收到 `state` + `sensor`；④ 串口 `status` 与 MQTT `state` 内容一致；⑤ 拔掉网线/WiFi 后重连，broker 上能看到 `offline` → `online`。 |

## 2. 需求 → 模块 对照总表

| 需求 | 主责模块 | 参与模块 | 控制入口 | 关键配置/宏 | 验收命令 |
|------|----------|----------|----------|-------------|----------|
| ① 光照联动 | `App/automation.c` 规则1 | `SENSOR` `ADC` `LED` `SERVO` `device_model` | 自动 | `light_on_lux`/`light_off_lux`/`auto_light_enable` | `status`、`cfg light_on_lux 50` |
| ② 温湿度显示+风扇 | `BSP/SENSOR/sensor.c`、`BSP/OLED/oled.c` | `automation` 规则2、`FAN`、`VOICE` | 自动 / 语音 | `temp_fan_on_c`/`temp_fan_off_c`/`fan_auto_speed` | `status`、`say fan_on` |
| ③ 雨滴关窗 | `App/automation.c` 规则3 | `SENSOR` `ADC` `SERVO` `device_model` | 自动 | `rain_pct`/`auto_rain_enable`/`auto_window_reopen` | `status`、`cfg rain_pct 30` |
| ④ 四路 LED + 语音 | `BSP/LED/led.c`、`BSP/WS2812/ws2812.c` | `device_model`、`VOICE` | 语音 / 按键 / 串口 / MQTT | `BSP_WS2812_GPIO_*`、`BSP_WS2812_LED_NUM_*` | `on led_living`、`say led_all_on` |
| ⑤ 舵机开门 | `BSP/SERVO/servo.c` | `device_model`、`VOICE`、`mqtt_app` | 语音 / 串口 / MQTT | `BSP_SERVO_GPIO_DOOR`、`BSP_SERVO_MIN/MAX_PULSE_US` | `open door` |
| ⑥ 语音交互+播报 | `BSP/VOICE/voice.c`、`main.c::voice_on_cmd` | `device_model`、`SENSOR` | 语音 | `BSP_VOICE_*`、`voice_cmd_t`（26 项） | `help-voice`、`say query_all` |
| ⑦ 终端+手机 App | `main.c` 串口调试台、`App/mqtt_app.c` | `wifi_sta`、`mqtt_protocol`、`device_model` | 串口 / MQTT | `CONFIG_APP_WIFI_*`、`CONFIG_APP_MQTT_*` | `status`、MQTTX 发布 `cmd` |

**统一控制入口**：以上所有控制方式最终都只调用 `App/device_model.c` 的 `device_set_power()` / `device_set_level()` / `device_set_color()` / `device_toggle()` / `device_all_off()`。
每次调用带上 `ctrl_source_t`（`SRC_BOOT` / `SRC_LOCAL_KEY` / `SRC_VOICE` / `SRC_MQTT` / `SRC_AUTO`）标明"谁改的"。

## 3. 本期范围 vs 后续可扩展

### 本期交付（已实现，代码可编译可运行）

| 项 | 状态 | 说明 |
|----|------|------|
| 7 条需求全部功能 | ✅ 已实现 | 配件到货即插即用 |
| 配件缺失容错 | ✅ 已实现 | `board_init()` 逐个 try，失败只告警；OLED/传感器/语音/灯带/舵机任意缺失都不影响其余功能 |

| 双 OTA 分区 | ✅ 分区表已就绪 | `partitions-16MiB.csv` 有 `ota_0` / `ota_1` 各 4MB，但**本期未接入 OTA 逻辑** |
| 摄像头 | ⛔ 本期不启用 | 未占用任何引脚/组件，需要时按下面「后续可扩展路径」接入 |

### 后续可扩展路径

| 方向 | 现状 | 扩展方式 |
|------|------|----------|
| **摄像头（esp32-camera）** | 未接入，本期不启用 | 在 `components/` 下新建 `esp32-camera` 组件放入官方仓库源码；在 `main/idf_component.yml` 加 `espressif/esp32-camera: "^2.0.0"`。注意与本工程已占用的 GPIO 做资源重排。 |
| **离线语音（ESP-SR）** | 现用"串口命令词模块"方案 | ESP-SR 是**后续升级路径**：只需替换 `BSP/VOICE/voice.c` 内部的采集/解析实现，把识别结果翻译成 `voice_cmd_t` 后调用同一个 `voice_dispatch()`；`main.c::voice_on_cmd()` 一行都不用改。 |
| **在线云平台 + TLS** | 现用公共明文 broker | 改 `CONFIG_APP_MQTT_BROKER_URI` 为 `mqtts://...`，并补齐证书/CRT bundle 配置（当前 `mqtt_app.c` 未配置任何证书）。详见 [`05-MQTT协议.md`](05-MQTT协议.md) 安全章节。 |

| **I2C 扩展 IO** | 已预留地址宏 `BSP_I2C_ADDR_PCF8574`（0x20） | 需要更多 GPIO 时接 PCF8574。 |
