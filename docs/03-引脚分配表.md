# 03 · 引脚分配表

> **本表是 [`components/BSP/board_config.h`](../components/BSP/board_config.h) 的人读版本。**
> 那份头文件才是唯一的真源（single source of truth）—— 改引脚只改它，全工程自动跟着变。
> 如果你改过 `board_config.h`，请同步更新本文档。

目标板：**ESP32-S3-DevKitC-1**（模组 ESP32-S3-WROOM-1-**N16R8**，16MB Flash + 8MB Octal PSRAM）

## 2. 禁用 / 保留引脚 —— 这些脚**绝对不能接外设**

ESP32-S3 看着有 45 个 GPIO，实际能用的只有二十几个。下表这些踩了会出各种玄学问题（随机重启、PSRAM 数据错乱、烧录失败、USB 认不到）。

| GPIO | 状态 | 原因 |
|------|------|------|
| **26 – 32** | 不可用 | 模组内部 SPI Flash 专用（且根本没引出到排针） |
| **33 – 37** | **绝对禁用** | N16R8 的 **Octal PSRAM** 占用。33/34 未引出；35/36/37 引出了但已被 PSRAM 吃掉，接外设会导致 PSRAM 读写错乱、随机死机 |
| **19 / 20** | 禁用 | USB D- / D+。接外设会导致 USB 无法枚举 |
| **43 / 44** | 禁用 | UART0 控制台（日志输出 + 串口烧录） |
| **0** | 避免 | 启动 strapping，拉低会进下载模式 |
| **3** | 不用 | 启动 strapping（JTAG 源选择）。本方案直接绕开 |
| **45** | 禁用 | 启动 strapping（VDD_SPI 电压选择），上电必须为低或悬空 |
| **46** | 禁用 | 启动 strapping（内部下拉），上电不可被拉高 |
| **38** | 预留 | DevKitC-1 **v1.0** 的板载 RGB 灯在这里 |
| **48** | 已占用 | DevKitC-1 **v1.1** 的板载 RGB 灯在这里（本工程用作状态指示灯） |

### 还剩哪些是空的？

`GPIO13`、`GPIO38`、`GPIO39`、`GPIO40`、`GPIO41`、`GPIO42` —— 共 6 个，留给以后扩展（比如加人体感应、烟雾传感器、第二个 I2C 设备）。

> 想在 R8 模组上用 GPIO33~37 的同学注意：那是**八线 PSRAM** 的专用脚，不是"没用到的空脚"。

## 3. 各外设的引脚分配依据

### 3.1 I2C 总线（GPIO8 / GPIO9）

- 用 **I2C0**，速率 **400kHz**（快速模式）
- 一条总线挂 3 类器件，靠**地址**区分：

| 器件 | 地址 | 宏 |
|------|------|-----|
| SSD1306 OLED | `0x3C` | `BSP_I2C_ADDR_SSD1306` |
| SHT30 / SHT31 | `0x44` | `BSP_I2C_ADDR_SHT30` |
| AHT20 | `0x38` | `BSP_I2C_ADDR_AHT20` |
| BH1750 | `0x23` | `BSP_I2C_ADDR_BH1750` |
| PCF8574（预留扩展 IO） | `0x20` | `BSP_I2C_ADDR_PCF8574` |

- 上拉电阻：多数成品模块**板载已带 4.7kΩ**，直连即可。裸芯片需要自己加两个 4.7kΩ 到 3V3。
- 排错：开机日志里会打印 `I2C scan done, N device(s) found`，扫不到就说明接线/供电/上拉有问题。

### 3.2 ADC（GPIO1 / GPIO2）

- ESP32-S3 有 ADC1 和 ADC2，但 **WiFi 一开 ADC2 就不能用**，所以本工程**只用 ADC1**。
- 衰减 `ADC_ATTEN_DB_12`，量程约 **0 ~ 3100mV**，12 bit（0~4095）
- 光敏电阻接 `ADC1_CH0`（GPIO1），雨滴 AO 接 `ADC1_CH1`（GPIO2）

### 3.3 WS2812 灯带（GPIO4 / 5 / 6 / 7）

- ESP32-S3 总共只有 **4 个 RMT TX 通道**，4 个房间正好占满。
- 每路灯珠数量在 `board_config.h` 里定义，默认各 30 颗：

```c
#define BSP_WS2812_LED_NUM_LIVING   30   // 按你实际买的灯带改这里
#define BSP_WS2812_LED_NUM_KITCHEN  30
#define BSP_WS2812_LED_NUM_BEDROOM  30
#define BSP_WS2812_LED_NUM_BATH     30
```

> **这就是为什么板载状态灯不能用 RMT** —— 通道被占满了。它改用"位带"方式（关中断约 30µs 直接翻转 GPIO），刷新频率很低，没有任何影响。

### 3.4 舵机（GPIO15 / 16 / 17）

| 舵机 | GPIO | LEDC 通道 | 用途 |
|------|------|-----------|------|
| 窗帘 | GPIO15 | `LEDC_CHANNEL_0` | 需求①（光照联动）+ 语音 |
| 窗户 | GPIO16 | `LEDC_CHANNEL_1` | 需求③（雨滴联动）+ 语音 |
| 门 | GPIO17 | `LEDC_CHANNEL_2` | 需求⑤ + 语音 |

- 三路共用 `LEDC_TIMER_0`，**50Hz**，14 bit 分辨率（1 计数 ≈ 1.22µs）
- 脉宽范围 `500 ~ 2500µs`（对应 0° ~ 180°）
- 如果舵机转到头会"滋滋"响或抖动，把 `BSP_SERVO_MAX_PULSE_US` 从 2500 调小到 2400 试试

### 3.5 风扇（GPIO18 / GPIO14）

| 功能 | GPIO | 外设 | 说明 |
|------|------|------|------|
| PWM 调速 | GPIO18 | LEDC_TIMER_1 / CH3，**25kHz**，10 bit | 25kHz 超出人耳听觉，不会有 PWM 啸叫 |
| 测速 TACH | GPIO14 | 默认关闭 | `BSP_FAN_TACH_ENABLE` 设为 1 才启用 |

### 3.6 按键（GPIO10 / GPIO11）

- 按下接地，**内部上拉**，低电平有效
- 消抖 30ms，长按判定 2000ms
- 按键一端接 GPIO，另一端接 **GND**（不需要外接上拉电阻）

### 3.7 语音模块（GPIO47 / GPIO21，UART1）

| ESP32 侧 | GPIO | 接模块的 |
|---------|------|---------|
| UART1 TX | **GPIO47** | 模块 **RXD** |
| UART1 RX | **GPIO21** | 模块 **TXD** |

- 波特率 `9600`（多数串口命令词模块的默认值），8N1
- ⚠ **TX 和 RX 要交叉接**：ESP32 的 TX 接模块的 RX，反之亦然。这是最常见的接线错误。
- 兼容 SU-03T / ASRPRO / LD3320 / 天问 等"串口命令词"模块

## 4. 运行时阈值（不是引脚，但一起放这儿方便对照）

都在 `board_config.h` 里给了默认值，**运行时可以通过 MQTT 或串口调试台修改，改了会存进 NVS**：

| 参数 | 宏 | 默认值 | 含义 |
|------|-----|--------|------|
| 光照开灯阈值 | `BSP_DEF_LIGHT_ON_LUX` | 50 lux | 低于此值 → 开客厅灯 + 拉上窗帘 |
| 光照关灯阈值 | `BSP_DEF_LIGHT_OFF_LUX` | 200 lux | 高于此值 → 关客厅灯 + 拉开窗帘 |
| 温度开风扇 | `BSP_DEF_TEMP_FAN_ON_C` | 28 °C | 高于此值 → 开风扇 |
| 温度关风扇 | `BSP_DEF_TEMP_FAN_OFF_C` | 26 °C | 低于此值 → 关风扇 |
| 雨滴关窗 | `BSP_DEF_RAIN_PCT` | 30 % | 高于此值 → 判定下雨，关窗 |

> 每组开/关用了**两个不同的阈值**，这就是**迟滞（hysteresis）**：温度在 26~28°C 之间时风扇状态不变，避免在阈值附近反复横跳。

## 5. 改引脚的注意事项

1. **只改 `components/BSP/board_config.h`**，不要在别处硬编码 GPIO 号。全工程（含 `board.c` 的开机引脚表打印）都从那里取值。
2. 改完引脚后，如果新脚和 I2C/RMT/LEDC 有冲突，编译或运行时会暴露出来。
3. **不要动**第 2 节"禁用引脚"表里的任何脚。
4. `main/Kconfig.projbuild` 里只有 WiFi / MQTT / 周期这类**软件配置**，引脚不放在 Kconfig 里 —— 因为引脚属于硬件事实，放头文件里更直观、更好用 git diff 看。
