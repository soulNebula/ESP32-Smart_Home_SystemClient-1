# 02 系统架构

> 本文描述工程的分层结构、数据流、任务拓扑、组件依赖，以及几个关键设计决策的取舍。
> 所有任务名 / 栈大小 / 优先级 / 周期均从源码读出，引脚与宏名取自 `components/BSP/board_config.h`。

## 1. 分层架构

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  应用入口  main/                                                             │
│    app_main()  · 串口调试台 serial_console_task  · 按键/语音 → 业务映射       │
│    app_loop_task：automation_tick + OLED 刷新 + 状态灯                        │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                │ 只调用 App 层接口
┌───────────────────────────────▼──────────────────────────────────────────────┐
│  App 业务层  components/App/                                                 │
│    device_model  ← 全屋设备统一状态机（唯一控制汇聚点）                        │
│    automation    ← 光照/温度/雨滴三条联动规则 + 双阈值迟滞 + NVS 持久化        │
│    wifi_sta      ← WiFi STA 自动重连、IP/RSSI、MAC 后缀唯一 ID                │
│    mqtt_app      ← esp-mqtt 客户端：订阅 cmd/config/get，上报 state/sensor/…  │
│    mqtt_protocol ← topic 规划与拼装（base = 前缀/唯一ID）                     │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                │ 只调用 BSP 语义接口（App 层不出现任何 GPIO 号）
┌───────────────────────────────▼──────────────────────────────────────────────┐
│  BSP 硬件层  components/BSP/                                                 │
│    board          ← board_init() 按顺序逐个 try 初始化，失败只告警             │
│    board_config.h ← ★ 全工程唯一引脚真源                                      │
│    I2C  ADC  WS2812  LED  SERVO  FAN  SENSOR  OLED  VOICE  KEY                │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                │ ESP-IDF 驱动
┌───────────────────────────────▼──────────────────────────────────────────────┐
│  ESP-IDF v5.4  driver 组件：i2c_master · ledc · rmt · gpio · uart · adc_oneshot│
│  App 侧：esp_wifi · esp_netif · esp_event · mqtt(esp-mqtt) · json(cJSON) ·     │
│          nvs_flash · esp_timer                                                 │
└───────────────────────────────┬──────────────────────────────────────────────┘
                                ▼
   硬件：4×WS2812 灯带 · 3×舵机 · MOS+风扇 · SHT30/AHT20 · BH1750/光敏电阻 ·
         雨滴模块 · SSD1306 OLED · 2×按键 · 语音模块 · 板载 RGB 状态灯
```

**分层纪律**：应用层只认 BSP 的语义接口（`led_set_power(LED_ZONE_LIVING, ...)`），**App 层源码里不出现任何 GPIO 号**。

## 2. 数据流

### 2.1 传感器 → 联动规则 / MQTT（自动上行）

```text
  [SHT30/AHT20 0x44/0x38]  [BH1750 0x23 或 光敏电阻 GPIO1]  [雨滴 AO GPIO2]
             │ I2C             │ I2C / ADC1_CH0                    │ ADC1_CH1
             └────────┬────────┴──────────────────────────────────┘
                      ▼
        BSP/SENSOR/sensor.c  ── 自动识别 + CRC 校验 + 一阶低通滤波(α=0.30)
                      │  写入静态缓存 s_data（临界区保护，sensor_get_last() 永不为 NULL）
        ┌─────────────┴──────────────┐
        ▼                            ▼
  app_loop_task (500ms)        mqtt_publish_sensor()
  ├─ automation_tick()         ① 周期上报（CONFIG_APP_MQTT_PUBLISH_SENSOR_MS，默认 2s）
  │  规则1/2/3 + 迟滞 + 手动保护期   ② 连接成功时一次  ③ 收到 <base>/get 时一次
  │      └─ device_set_*(SRC_AUTO) ──► 见 2.2
  └─ astra UI 刷新（main/astra_glue.cpp）→ u8g2 画布 → oled_write_page()
```

> 传感器周期上报由 `app_loop_task` 按 `CONFIG_APP_MQTT_PUBLISH_SENSOR_MS` 节拍调用
> `mqtt_publish_sensor()` 完成（`main.c`）。所以手机端**不用**主动发 `/get` 也能持续收到温湿度。

### 2.2 控制指令 → 硬件（所有入口汇聚到 device_model）

```text
  语音模块 UART1 ─→ voice.c ─→ voice_dispatch() ─┐
  串口 say <cmd> ─→ voice_inject_cmd() ──────────┤（与真实语音走完全相同链路）
                                                 ▼
                                        main.c::voice_on_cmd()
                                                 │
  板载按键 GPIO10/11 ─→ key.c 扫描任务 ─→ key_on_event() ─┤
                                                 │        │
  手机 App / MQTTX ─→ base/cmd · base/config · base/get ──┤
                                                 ▼        ▼
                        automation.c ──(SRC_AUTO)──►  ┌──────────────────────────┐
                                                     │  App/device_model.c      │
                                                     │  device_set_power()      │
                                                     │  device_set_level()      │
                                                     │  device_set_color()      │
                                                     │  device_toggle()         │
                                                     │  device_all_off()        │
                                                     └───────┬──────────────────┘
                                                             │ ① 改软件状态（互斥锁保护）
                                                             │ ② 调 BSP 真正操作硬件
                                                             │ ③ 锁外回调通知上层
                     ┌───────────────────────────────────────┼────────────────────┐
                     ▼                                       ▼                    ▼
              BSP: led / servo / fan            device_changed_cb()      automation_notify_manual()
              (WS2812 RMT · LEDC · LEDC)        → base/state (retain)    → 开 3 秒手动保护期
```

**核心设计**：`device_model` 是**唯一**的状态真源和硬件出口。
任何控制入口都不直接调 `led.c` / `servo.c` / `fan.c`，因此"谁在什么时候把灯改了"始终可追溯（`ctrl_source_t`），
定时上报与手动保护期也只需要在一个地方挂钩。

## 3. 任务拓扑

| 任务名 | 创建者 | 栈（字节） | 优先级 | 周期 / 阻塞方式 | 源码位置 |
|--------|--------|-----------|--------|-----------------|----------|
| `main`（`app_main`） | ESP-IDF 启动代码 | `CONFIG_ESP_MAIN_TASK_STACK_SIZE` = **8192** | IDF 默认 | 初始化完**返回**，不常驻 | `main/main.c` |
| `app_loop` | `app_main` | **4096** | **5** | 500 ms 循环（`vTaskDelay`） | `main/main.c` |
| `console` | `app_main` | **4096** | **3** | `uart_read_bytes` 100 ms 超时 | `main/main.c` |
| `sensor_auto` | `sensor_start_auto()` | **4096** | **4** | `CONFIG_APP_SENSOR_PERIOD_MS`（默认 1000 ms，下限 100 ms） | `SENSOR/sensor.c` |
| `key_scan` | `key_init()` | **3072** | **4** | 10 ms 固定周期（`vTaskDelayUntil`） | `KEY/key.c` |
| `voice_rx` | `voice_init()` | **3072** | **3** | `uart_read_bytes` 100 ms 超时 | `VOICE/voice.c` |
| `mqtt_task` | esp-mqtt 内部 | `CONFIG_MQTT_TASK_STACK_SIZE` = **6144** | `MQTT_TASK_PRIORITY` = **5** | 事件驱动（socket 阻塞读） | `App/mqtt_app.c` 配置 |
| `esp_timer` | IDF `esp_timer_init()` | `CONFIG_ESP_TIMER_TASK_STACK_SIZE` = **3584**（IDF 默认） | IDF 内部高优先级 | 板载状态灯闪烁（`period_ms` 150/500 ms） | `LED/led.c` |

> 还有 IDF 内部的 `ipc0` / `ipc1`、`wifi`、`esp_event`、`sys_evt` 等任务，本工程未修改其参数。
> `app_loop` 与 `mqtt_task` 同为优先级 5，靠 FreeRTOS 时间片交替；`app_loop` 每轮只有 `automation_tick` + 一次 OLED 刷新，且 `automation_tick` 内**没有任何阻塞调用**（联动里刻意不用 `servo_set_angle_smooth()`），所以不会把 MQTT 任务饿死。

**任务间通信**：没有使用队列/信号量做业务解耦，而是：
- 共享数据用互斥锁保护（`device_model.c` 的 `s_lock`、`automation.c` 的 `s_lock`）；
- 传感器数据用临界区保护的整体结构体拷贝（`sensor.c` 的 `s_data_mux`）；
- 状态变化用**回调**通知（`device_register_cb`，锁外执行）；
- **回调里不做阻塞操作**（`key.c` / `voice.c` 文件头都有明确警告）。

## 4. 组件依赖

`components/` 下实际有 4 个组件：

```text
        main  ──────────────────────────────────────────────┐
          REQUIRES: BSP App driver nvs_flash esp_wifi        │
                 │                                           │
       ┌─────────┴─────────┐                                 │
       ▼                   ▼                                 │
     App                  BSP                                │
  REQUIRES:            REQUIRES:                             │
   BSP                  driver     (gpio/i2c/ledc/rmt/uart/  │
   driver                         gptimer/pcnt 汇总组件)     │
   esp_wifi             esp_adc    (adc_oneshot + adc_cali)  │
   esp_netif            esp_timer  (舵机平滑转动用)            │
   esp_event            esp_ringbuf                           │
   mqtt   (esp-mqtt)                                          │
   json   (cJSON)                                             │
   nvs_flash                                                  │
   esp_timer                                                  │
       │                                                      │
       └──────────────────────────────────────────────────────┘
  astra_ui:  REQUIRES BSP（C++，OLED 菜单框架 + u8g2 画布 HAL）
  u8g2:      独立组件，无依赖
```

依赖方向单向：`main → App → BSP → IDF 驱动`，**BSP 不反向依赖 App**（所以 OLED 的文字/数值由 App 侧算好后交给 astra UI 画布渲染）。

## 5. 「配件缺失也能跑」的设计

| 设计点 | 实现方式 | 源码 |
|--------|----------|------|
| 板级初始化逐个 try | `board_init()` 把 10 个模块的 `esp_err_t` 收集到 `results[]`，逐条打印 `[ OK ]` / `[FAIL]`，**任何失败都不 return 致命错误**；只要有失败就返回 `ESP_ERR_NOT_FOUND` 提示 | `BSP/board.c` |
| 主流程忽略该错误 | `app_main()` 里写的是 `(void)board_init();` —— 明确表示"返回值仅供参考" | `main/main.c` |
| OLED 不接 = 空操作 | `oled_init()` 探测失败即 `s_ready=false`，之后所有绘制/刷新函数直接 return，绝不 `ESP_ERROR_CHECK` / assert | `OLED/oled.c` |
| 灯带单路缺失 | `led_init()` 每条灯带单独 try，失败的 zone 标记 `inited=false`，`apply_zone()` / `zone_refresh()` 遇到它直接返回 `ESP_OK` | `LED/led.c` |
| 传感器自动识别 | 温湿度：探测 `0x44`(SHT30/SHT31) → 否则 `0x38`(AHT20) → 都没有则 `valid_temp=false`；光照：探测 `0x23`(BH1750) → 否则退回光敏电阻 ADC。**全部缺失 `sensor_init()` 仍返回 `ESP_OK`** | `SENSOR/sensor.c` |
| 传感器热插拔 | 每 `SENSOR_REPROBE_PERIOD_MS`(5000ms) 重新探测"开机时没插上"的器件；连续失败 3 次才判掉线 | `SENSOR/sensor.c` |
| 温度联动自动停用 | 联动里判断 `d->valid_temp`，无温湿度时规则2 直接不执行 | `App/automation.c` |
| 光照数据有效性 | `light_data_valid()`：BH1750 在线即有效；光敏模式下 `light_mv` 或 `light_pct` 非 0 才算有效 —— 防止"没插传感器 → 读数恒 0 → 被误判成屋里全黑 → 灯一直亮" | `App/automation.c` |
| 语音模块没接 | `voice_init()` 照常装 UART 驱动并起接收任务（100ms 超时空转，不报错、不刷屏）；业务全靠 `voice_inject_cmd()` 注入跑通 | `VOICE/voice.c` |
| 硬件写失败不改软件状态 | `device_model.c` 的 `hw_set_*()` 里 BSP 返回错误**只告警**，软件状态依然生效 —— 方便没插硬件时联调 MQTT / OLED | `App/device_model.c` |

## 6. 目录 / 组件发现机制

ESP-IDF 的组件发现规则（见 `$IDF_PATH/tools/cmake/project.cmake` 的 `__project_component_dir`）：

- `components/` 下**每个自带 `CMakeLists.txt` 的直接子目录** = 一个组件；
- 若该子目录**自己没有** `CMakeLists.txt`，则只再向下递归**一层**找组件。

由此：

| 目录 | 是否组件 | 原因 |
|------|----------|------|
| `components/BSP/` | ✅ 一个组件 | 有 `CMakeLists.txt`，把 `KEY/ ADKEY/ LED/ I2C/ ADC/ WS2812/ SERVO/ FAN/ SENSOR/ OLED/ VOICE/` 全部登记在它的 `SRCS` 与 `INCLUDE_DIRS` 里。**这些子目录不需要各自的 `CMakeLists.txt`** |
| `components/App/` | ✅ 一个组件 | 有 `CMakeLists.txt` |
| `components/astra_ui/` | ✅ 一个组件 | OLED 菜单框架（C++，含 u8g2 画布 HAL） |
| `components/u8g2/` | ✅ 一个组件 | 图形库（`file(GLOB csrc/*.c)`；用不到的驱动/字体靠 `gc-sections` 裁掉） |

> 2026-09-29 清理：原先还有一个 `components/Middlewares/esp32-camera/` 占位组件（8 个空目录 + 1 个 CMakeLists，
> 从没启用过，IDF 构建时还会报 "does not contain a CMakeLists.txt"），已删除。

> ⚠ 不要为了加 `components/BSP` 而设置 `EXTRA_COMPONENT_DIRS` —— 默认扫描已经会加上它，重复添加会导致"组件重名"报错。

## 7. OLED 文字渲染链路（astra UI + u8g2）

```text
  astra UI（components/astra_ui，从 RID 接收机项目移植）
        │  每帧把页面数据写进菜单项标题（main/astra_glue.cpp 的 refresh_*）
        ▼
  u8g2 全缓冲画布（components/u8g2；中文字体 u8g2_font_wqy12_t_gb2312，行高 13px）
        │  canvasUpdate() → 逐页回调 flush_page_cb()
        ▼
  oled_write_page(page, data)      ← components/BSP/OLED/oled.c
        │  直接写 SSD1306 的 128 字节页（不经内部显存）
        ▼
  SSD1306 128x64
```

要点：

* **排版**：行基线统一放在 `astra/config/config.h`（`rowTitleY / rowBigY / row3Y / row4Y`）。
  64px 高只放得下 4 行（中文 13px、10x20 大字号 17px）。**改排版先跑 `tools\run_ui_preview.ps1`**
  在电脑上看行重叠，别直接烧板子 —— 见 [docs/12](12-OLED排版与PC预览工具.md)。
* **字符集**：wqy12 是 **GB2312** 字集。生僻字/emoji 会显示成方块 → 换常见同义字最省事；
  想换字体就改 `mainFont`（例如 `u8g2_font_wqy16_t_gb2312`），**但行高会变、必须重排**。
* **历史（2026-09-29 删除）**：早期还有一套自绘字库（6x8 / 8x16 ASCII + 16x16 中文，由
  `tools/gen_font.ps1` 生成 `components/BSP/OLED/oled_font.c`）以及仪表盘 / 开机画面 / 提示框绘制
  （`oled_draw_str` / `oled_printf` / `oled_show_dashboard` …）。换成 astra UI 之后这些**全工程零调用**，
  已连同生成脚本一起删除；`oled.c` 现在只保留 初始化 / 探测 / 清屏 / 整屏刷新 / 按页写入。

## 8. 关键设计决策与取舍

| # | 决策 | 为什么这么做 | 代价 / 取舍 |
|---|------|--------------|-------------|
| 1 | **阈值判断用双阈值迟滞** | 单阈值时，光照/温度在临界点抖动会让灯、风扇疯狂开关。用 `light_on_lux`(50) / `light_off_lux`(200) 和 `temp_fan_on_c`(28) / `temp_fan_off_c`(26) 两个阈值，中间区间保持不动 | 阈值配置变复杂（有交叉约束：`off` 必须大于/小于 `on`），发 JSON 时键顺序会影响结果 |
| 2 | **自动联动有手动保护期**（`AUTO_MANUAL_GUARD_MS = 60000`，2026-09-29 由 3000 调大） | 你刚用手机开灯，自动规则立刻又给关掉，体验极差。`device_model` 在 `SRC_MQTT` / `SRC_VOICE` / `SRC_LOCAL_KEY` 时自动调 `automation_notify_manual()`，规则在保护期内跳过该设备。**实测 3 秒太短** —— App 里开灯 3 秒后就被规则覆盖，体感像程序在跟人抢，故提到 1 分钟 | 手动操作后 **60 秒内**自动联动"失效"；`SRC_AUTO` 自己触发的动作不会开保护期（否则规则会自己把自己锁死） |
| 3 | **4 路灯带占满 RMT 通道 → 状态灯改用位带** | ESP32-S3 只有 **4 个 RMT TX 通道**，正好被 4 个房间的灯带全部占用。板载状态灯刷新频率极低（状态变化或闪烁节拍，150/500ms），用位带（关中断约 30us 写 1 颗）完全够用 | 位带期间短暂关中断；不适合高频/多颗灯珠场景（所以只用于 1 颗状态灯） |
| 4 | **MQTT 的 `device_model` 回调槽位独占，不做多订阅** | `device_register_cb()` **只保留最后一个**回调。MQTT 需要"状态一变就上报"，OLED 不需要回调（由 `app_loop` 定时刷新），所以槽位让 MQTT 独占，不需要引入回调链表 | 以后若还想让别的模块订阅状态变化，必须先给 `device_model` 加多订阅支持，否则后注册的会把 MQTT 顶掉（`mqtt_app.c` 里已写明这个警告） |
| 5 | **所有控制入口只调 `device_model` 的 set 接口** | 单一汇聚点：状态真源唯一、`ctrl_source_t` 可追溯、上报与保护期只挂一处；语音/按键/MQTT/自动四条链路的语义（比如舵机 `open` ≡ `set 100`）保持一致 | `device_model` 成为核心热点，改动它影响面大；每次 set 会短暂持锁（BSP 写入都在锁内，要求 BSP 不阻塞 —— 所以联动里绝不用 `servo_set_angle_smooth()`） |
| 6 | **配置存 NVS 用「magic + version + size + 配置体」的 blob** | 直接存 `automation_cfg_t` 会遇到结构体 padding 和"以后加字段"问题。加头之后，旧固件写的数据不会被新固件误读成乱码，读不合法就整块丢弃回默认值 | 多 8 字节头和一次校验；改结构体要同步 +1 `AUTO_CFG_VERSION` 并写迁移 |
| 7 | **按键用轮询 + 软件消抖，不用 GPIO 中断** | 机械按键抖动会产生大量边沿，走中断容易中断风暴，还要在 ISR 里回避日志/回调限制。2 个按键用 10ms 轮询毫无压力，消抖判断也更直观 | 最长 30ms 的响应延迟（`BSP_KEY_DEBOUNCE_MS`），对家居场景无感 |
| 8 | **WS2812 / SSD1306 / SHT30 / AHT20 / BH1750 全部自研，不用在线组件** | 保证**无网环境 `idf.py build` 一次通过**，课堂/交付现场不会因为拉不下面包而卡住 | 驱动要自己维护；`main/idf_component.yml` 里只声明 `idf: >=5.4.0` |
| 9 | **光照「等效 lux」是平方曲线折算**（`lux = pct²/100 × 5`） | 光敏电阻的 ADC 百分比是线性的，但人眼/场景对暗区更敏感。平方折算让暗区更细腻，且让默认阈值 50/200 lux 正好落在"比较暗"和"比较亮"的位置 | **这不是真实 lux**。换成 BH1750 后读到真实 lux，量级差很多，`BSP_DEF_LIGHT_ON_LUX` / `BSP_DEF_LIGHT_OFF_LUX` 必须重新标定（`sensor.c` 文件头已注明） |
