# 使用说明：哪个文件干什么

> 完整技术说明见 [工程根目录的 README](../README.md)，这里只讲"怎么用"。

## 一句话

改完代码 → **用你自己系统的那条命令**启动 → 点「一键编译烧录」。

```bat
:: Windows
python .idf-sandbox\start.py
```

```bash
# Linux
python3 .idf-sandbox/start.py
```

## 零、先看这里：环境是空的？点一下「配置沙箱环境」

从 GitHub 上 clone 下来，或者别人只发给你源码包 —— 这时候 `.idf-sandbox/`
里**只有脚本，没有环境**（编译器、ESP-IDF 都得现下，一共 3.6 GB，GitHub 放不下）。

打开图形控制台，点工具栏第一个按钮 **「配置沙箱环境」**：

```
[配置沙箱环境] [环境体检] [修复沙箱] [WiFi 配置]      [打开日志] [清空输出]
```

它会自己从官方源把缺的东西下齐：

| 下什么 | 从哪下 | 多大 |
|---|---|---|
| ESP-IDF 5.4.4 源码 | `dl.espressif.com`（官方国内镜像） | 1.9 GB |
| xtensa 交叉编译器 | 同上 | 约 250 MB |
| CMake / Ninja / ROM 链接脚本 | 同上 | 约 55 MB |
| ESP-IDF 的 Python 依赖 | PyPI | 约 60 MB |
| esp-sr 语音组件 | `components.espressif.com` | 约 230 MB |

**全部落在 `.idf-sandbox/` 里面**，不装 C 编译器、不改 PATH、不写注册表、
不装全局 Python 包。不想要了，把文件夹删了就干净了。

命令行一样能跑：

```bat
python .idf-sandbox\start.py prepare --download     :: Windows
```
```bash
python3 .idf-sandbox/start.py prepare --download    # Linux
```

配套的两个命令（一般用图形界面上的按钮就行）：

```bat
python .idf-sandbox\start.py prepare --check          :: 自检：每项都真跑一遍
python .idf-sandbox\start.py prepare --prune          :: 看能清理多少（不删）
python .idf-sandbox\start.py prepare --prune --yes    :: 真删，腾硬盘
python .idf-sandbox\start.py prepare --fetch linux    :: 在 Windows 上给 Linux 备好工具链
```

**下完自动自检**（每一项都真的执行一遍，不是只看文件在不在）：

```
--- 自检 ------------------------------------------------------
  [OK]   ESP-IDF 源码        5.4.4
  [OK]   Python 环境         3.14.0
  [OK]   交叉编译器          xtensa-esp-elf-gcc-14.2.0 ...
  [OK]   idf.py 端到端       ESP-IDF v5.4.4
  [OK]   组件依赖            232.7 MB
  [OK]   自检全部通过 —— 可以点"一键编译烧录"了
```

> **断了不要紧**：再点一次会接着下，已经下好的跳过，压缩包解压完立刻删掉。

## 一、日常就一条命令

**`start.py` 是整个沙箱的总入口** —— 启动逻辑（认系统、选工具链、检查版本、
换解释器）全写在它这一个文件里，不依赖任何东西。跑起来就是图形控制台。

### 先选对系统

沙箱里 **Windows 和 Linux 两套工具链都装了**（各占各的目录）。用哪套：

| 你的系统 | 双击/执行 | 或命令行 |
|---|---|---|
| **Windows** | `.idf-sandbox\启动-Windows.cmd` | `python .idf-sandbox\start.py` |
| **Linux** | `sh .idf-sandbox/start-linux.sh` | `python3 .idf-sandbox/start.py` |

其实不选也行 —— `start.py` 会自己认出当前是什么系统。
**两套都装了的沙箱，第一次运行会问你要用哪一套**，问过就记住了。
想跳过询问直接指定：

```bat
python .idf-sandbox\start.py --os windows
python3 .idf-sandbox/start.py --os linux
```

> **为什么不能一套通用**：工具链是可执行文件，Windows 的是 `.exe`（PE 格式），
> Linux 的是 ELF 格式，**内核互相不认**。选错了会明确告诉你，不会一堆看不懂的报错。
> 以前在 Linux 上点 Windows 沙箱，每个按钮都报
> `Exec format error` —— 现在这种情况会被提前拦住并说清楚。

### 任务（两个系统一模一样）

| 命令 | 干什么 |
|---|---|
| `start.py` | 图形控制台（默认） |
| `start.py run` | 编译 + 烧录 + 看串口，一条龙 |
| `start.py build` | 只编译，**板子没插也行** |
| `start.py flash` | 只烧录 |
| `start.py monitor` | 只看串口 |
| `start.py doctor` | 环境体检 |
| `start.py prepare` | 准备 / 修复沙箱 |
| `start.py --help` | 看全部 |

参数照常接在后面：`start.py build --clean`、`start.py run -p COM31 --erase`、
`start.py run -p /dev/ttyUSB0`。

### Linux 上第一次要多一步

Linux 那套的**工具链**是打包好的，但 Python 依赖得装一次（Windows 侧是拷现成的）：

```bash
python3 .idf-sandbox/start.py prepare --download
```

要联网，几分钟，**只做这一次**。之后完全离线。
其实不跑也行 —— 第一次点按钮时它自己会做，只是屏幕上会先滚一段安装日志。

Linux 上还建议先加串口权限（不加会报 `Permission denied`）：

```bash
sudo usermod -aG dialout $USER     # 之后要重新登录一次
```

### 也能双击

沙箱目录（`.idf-sandbox\`）里那几个中文名的 `.py` 是上面命令的**双击版**，图省事用的：

| 双击这个 | 等于 |
|---|---|
| `一键编译烧录.py` | `python .idf-sandbox\start.py run` |
| `只编译.py` | `python .idf-sandbox\start.py build` |
| `只看串口.py` | `python .idf-sandbox\start.py monitor` |
| `环境体检.py` | `python .idf-sandbox\start.py doctor` |
| `修复沙箱.py` | `python .idf-sandbox\start.py prepare` |

它们只有十行，转发给 `start.py`，没有自己的逻辑。命令行里两条路等价，
`python .idf-sandbox\只编译.py` 和 `python .idf-sandbox\start.py build` 干的是同一件事。

**Windows 上最省事的是双击 `.idf-sandbox\启动-Windows.cmd`** ——
它直接用沙箱自带的 Python，所以这台电脑装没装 Python、`.py` 有没有关联，都不影响。
Linux 上等价的是 `sh .idf-sandbox/start-linux.sh`。

| 想改什么 | 改哪个文件 |
|---|---|
| WiFi 名和密码 | `components/App/wifi_config.h`（就两行） |
| 引脚定义 | `components/BSP/board_config.h` |

## 三、不用碰的：环境（跟着工程一起拷）

**`.idf-sandbox/`** —— 约 3.3 GB，编译器 + Python + ESP-IDF 全在这里面（含 Windows 和 Linux 两套）。
不要删、不要改、**不要只拷一半**。它是"客户机什么都不用装"的全部底气。

里面各是什么：

| 目录 | 是什么 |
|---|---|
| `idf/` | ESP-IDF 5.4.4 源码（**两个平台共用这一份**） |
| `python/`、`penv/` | Windows 的便携 Python 3.11.2（含图形界面要用的 Tcl/Tk） |
| `idf_tools/` | Windows 的 xtensa gcc 14.2、CMake、Ninja（`*.exe`） |
| `drivers/` | USB 转串口驱动（只有 Windows 要装） |
| `penv-linux/` | Linux 的虚拟环境（用系统 `python3` 建的） |
| `idf_tools-linux/` | Linux 的 xtensa gcc、CMake、Ninja（ELF） |
| `tmp/`、`logs/` | 自动生成，不用管 |

哪一套生效，由 `start.py` 按当前系统自动选；也可以 `--os windows` / `--os linux` 指定。

## 四、不用碰的：脚本实现

**`.idf-sandbox/tools/*.py`** —— `start.py` 背后真正干活的地方，全是 Python。

| Python 文件 | 谁在用它 |
|---|---|
| `gui.py` | `start.py`（默认任务，图形界面） |
| `run.py` | `start.py run` / `一键编译烧录.py` |
| `build.py` | `start.py build` / `只编译.py` |
| `flash.py` | `start.py flash` |
| `monitor.py` | `start.py monitor` / `只看串口.py` |
| `doctor.py` | `start.py doctor` / `环境体检.py` |
| `prepare.py` | `start.py prepare` / `修复沙箱.py` |
| `core.py` | 不是入口，上面几个共用的地基（找沙箱、拼环境变量） |
| `start-linux.sh` | Linux 上的入口壳（挑 Python 然后转给 start.py） |

> 根目录的 **`start.py` 才是入口**，里面有全部启动逻辑（版本检查、找沙箱、
> 换解释器、分发任务）。上面这些是它调用的实现。

`tools/build/*.ps1`、`tools/monitor/*.ps1`、`tools/verify/*.ps1` 是**以前留下的老脚本**。
Python 版功能更全、不依赖 PowerShell，老脚本只是备用，**可以完全不看**。

### 启动的到底是哪个 Python？

分四步，别搞混：

```
你敲的 python .idf-sandbox\start.py
  │
  ├─ 1. Windows 按文件关联挑解释器 —— 这台机器上是 py.exe（Python 官方启动器）
  │
  ├─ 2. start.py 检查版本，然后**换成沙箱里的解释器重跑一遍**
  │       python.exe / pythonw.exe  跑 .idf-sandbox\tools\<某个>.py        ← 第 1 层
  │
  ├─ 3. 要编译时：penv\Scripts\python.exe 跑 idf\tools\idf.py        ← 第 2 层
  │
  └─ 4. 交叉编译器 xtensa-esp32s3-elf-gcc                            ← 第 3 层
```

- **第 2 步是关键**：不管你系统里装的是 3.9 还是 3.14，最终跑的都是沙箱那套，
  行为统一，图形界面要的 tkinter 也一定有。
  沙箱 Python 万一没了，它就老实待在系统解释器里跑（脚本本身兼容 3.9~3.14）。
- **第 3 层和第 1 层是两个不同的 Python**，这是故意的 —— ESP-IDF 对版本有要求。
- 图形界面里点「一键编译烧录」**不会再开一个 Python 进程**，
  而是在 `gui.py` 自己的进程里直接调用 `run.py` / `build.py` / `flash.py` 里的函数。

实测的进程命令行长这样（用系统 Python 3.14 敲 `python .idf-sandbox\start.py`，它自己切成了沙箱的 pythonw）：

```
C:\...\.idf-sandbox\python\pythonw.exe  C:\...\start.py
```

想确认实际用的是哪个：

```bat
python .idf-sandbox\环境体检.py       :: 里面有一行"跑本脚本的 Python"
```

想关掉自动切换（排查问题时有用，报错不会被 pythonw 吞掉）：

```bat
set ESP32_NO_RELAUNCH=1
python .idf-sandbox\start.py
```

**没有 `main.py` 这种唯一入口** —— 入口就是你双击的那个文件，
它们都只是薄薄一层，转给 `.idf-sandbox\tools\` 里对应的脚本。

## 五、自动生成的：别来回拷

| 目录 | 说明 |
|---|---|
| `build/` | 编译产物，约 250 MB，删了下次自动重建 |
| `logs/` | 编译 / 烧录 / 串口日志，可以随便删 |
| `.idf-sandbox/tools/__pycache__/` | Python 缓存，可以随便删 |
| `.idf-sandbox/tmp/` | 编译临时文件，自动清理 |
| **`managed_components/`** | ⚠️ **这个例外，必须带！** esp-sr 语音组件，233 MB，删了就得联网重下 |

## 三个场景怎么做

### 场景 1：第一次拿到这个工程

1. 把**整个文件夹**拷到电脑上（U 盘 / 网盘都行），**路径尽量纯英文**
2. 插上板子。认不出来就先装一次驱动 —— 看 `.idf-sandbox/drivers/README.md`
3. 双击 `start.py`
4. 点「一键编译烧录」，等它跑完：会自动编译 → 烧录 → 打开串口
5. 窗口底下的输入框可以直接给板子发命令，比如敲 `status` 回车

第一次编译约 2~3 分钟；之后改一行代码再编只要几秒。

### 场景 2：改了代码要重新烧

双击 → 点「一键编译烧录」→ 完事。

只想知道有没有写错，点「只编译」，不用插板子。

### 场景 3：出问题了

1. 双击 `环境体检.py`，把屏幕截图发出来
2. 它报"缺 xxx" → 双击 `修复沙箱.py`
3. 串口一个都扫不到 → 装驱动（`.idf-sandbox/drivers/README.md`）
4. 想编**别的工程** → 控制台顶上「工程」那一行，点「浏览…」（默认从桌面开始翻）

## 交付给客户：拷什么

**整个文件夹直接拷**，最简单也最不容易出错。
（瘦身后约 **3.9 GB**：沙箱 3.31 GB + 语音组件 233 MB + 源码）
拷贝完客户那边只需要做一件事：`python .idf-sandbox\start.py`。

想先瘦身再拷（能省约 250 MB）：

| ✅ 可以删 | ❌ 千万别删 |
|---|---|
| `build/` | **`.idf-sandbox/`**（除了 logs 和 tmp，整个都要） |
| `.idf-sandbox/logs/`、`.idf-sandbox/tmp/` | **`managed_components/`** |
| `.idf-sandbox/tools/__pycache__/` | `CMakeLists.txt`、`main/`、`components/` |
| `android/.gradle/`、`.vscode/` | `sdkconfig`、`partitions-16MiB.csv` |

打包时用 7-Zip 之类支持 Zip64 的工具；Windows 自带的"压缩(zipped)文件夹"
对 2 GB 以上的包容易出问题。或者干脆拷文件夹，不打包。

> ### ⚠️ 别用 `git clone` 交付
>
> `.gitignore` 把沙箱的环境部分（`.idf-sandbox/python/`、`idf/`、`idf_tools/`）
> 和 `managed_components/` 都排除了（体积太大），clone 下来只有源码 + 脚本。
> 客户那边会报"沙箱不完整"，编译也找不到 esp-sr。
>
> 要交付就**拷文件夹**或者**打压缩包**，别走 git。
